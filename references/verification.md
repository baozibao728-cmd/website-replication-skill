# 验收与交付证据

## 层级

资源归档只覆盖声明清单，不等于服务器全部资源。可交互镜像需在本地运行并对照视觉；可维护重建另需工程构建和功能验证，不等于自动恢复原源码。

| 等级 | 证据 |
|---|---|
| L0归档 | manifest文件存在，大小/哈希/必要格式通过；失败与冲突已解决或明确部分 |
| L1本地运行 | 新浏览器上下文中入口/路由能加载，外部请求被阻断并记账，无致命页面错误 |
| L2交互 | 声明动作和状态执行，并通过人工/专门断言对照原站；执行完不单独证明一致 |
| L3视觉 | 相同视口/DPR/浏览器、对应数据与动画状态的截图对照 |
| L4字节抽检 | 归档与同次响应字节一致；运行时改写后的响应不称原样 |

## 工具

```sh
node scripts/verify.js ./work/mirror
# 保持 serve 在另一终端运行，再做阻断外网的浏览器冒烟：
node scripts/verify.js ./work/mirror --url "http://127.0.0.1:8080" --routes ./work/routes.json
# 可加入 --actions ./work/actions.json 复用明确动作
```

第一条只证明 L0。浏览器报告区分“访问/动作执行”和“与线上一致”，后者需要对照。

不要将 DevTools offline 阻断 localhost 当成缺资源。工具只允许本地服务请求，拦截外部 HTTP(S)/WebSocket，用新上下文避免旧缓存。Service Worker默认禁用保证拦截可观测；依赖SW的站点另在隔离外网环境验证真实SW流程并报告差异。

分别记录外网逃逸、4xx/5xx、资源返回HTML和页面异常；具体噪声需逐项判定，不全局忽略。首次进入、深链、站内跳转与刷新都应覆盖。

## 截图与交付

原站和镜像使用同套动作/视口，等待字体与关键内容，固定比较动画节点。动态时间、随机数据、GPU差异分别说明；阈值不能掩盖缺失内容。

交付报告列入口/时间、路由/视口/状态范围、条目数量、缺口/冲突、验证命令与实际等级、差异与未覆盖项。保存 coverage.json 和验证报告，只有实际通过才标完成。

维护测试使用 npm test。受限环境若禁止测试子进程，可 Node20+ 逐个执行 node tests/<name>.test.js；浏览器功能还需实际Chromium测试。
